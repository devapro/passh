# passh

[English](README.md) · Русский

> Перевод `README.md`. При расхождениях основным считается английский текст.

passh — менеджер паролей в одном файле, для одного человека. Пароли хранятся в **одном зашифрованном файле хранилища**, который можно скопировать куда угодно и проверить после копирования. Он открывается парольной фразой, а если вы её забыли — бумажным ключом восстановления. Всё внутри зашифровано с помощью [age](https://age-encryption.org), включая имена записей и теги, и если passh когда-нибудь не станет, хранилище откроет стандартная утилита `age`.

- Один статический бинарник для Linux (amd64, arm64, armv7, например Raspberry Pi) и macOS (Intel, Apple silicon). Без root, без GnuPG, без git, без служб.
- Работает одинаково локально и по обычному `ssh`, включая копирование в локальный буфер обмена (OSC 52).
- Папки и теги, нечёткий поиск, генератор паролей, TUI.
- Проверяемые копии, автоматические резервные копии, бумажный ключ восстановления.
- Односторонний импорт из `pass`; экспорт в CSV, JSON и Bitwarden JSON; печать текстового листа или через одноразовую страницу печати в браузере.

Подробнее: [EXAMPLES.md](EXAMPLES.md) (примеры использования, на английском), [spec.ru.md](spec.ru.md) (полная спецификация; основная версия — [spec.md](spec.md)).

## Установка

Скачайте со [страницы релизов](https://github.com/devapro/passh/releases) архив для своей платформы и файл `passh_<version>_checksums.txt`, проверьте архив и скопируйте бинарник в папку из `PATH`:

```bash
sha256sum -c --ignore-missing passh_<version>_checksums.txt   # macOS: shasum -a 256 -c --ignore-missing …
tar -xzf passh_<version>_linux_arm64.tar.gz
install -m 755 passh ~/.local/bin/passh
passh --version
```

На Raspberry Pi берите `linux_arm64` для 64-битной ОС и `linux_armv7` для 32-битной.

Если установлен Go 1.26 или новее, можно собрать и установить одной командой: `go install github.com/devapro/passh/cmd/passh@latest` (тогда бинарник сообщает версию `dev`).

Это всё: без root и без другого ПО. passh пишет только в файл хранилища, в свой конфигурационный файл (`~/.config/passh/config.toml`), в `~/.local/state/passh/` и, для `edit --editor`, во временную папку на tmpfs. Больше он ничего в системе не меняет. Бинарники релиза не подписаны. Если macOS блокирует бинарник, скачанный через браузер, выполните `xattr -d com.apple.quarantine ~/.local/bin/passh`.

## Быстрый старт

```bash
passh init                 # дважды спрашивает новую парольную фразу, создаёт хранилище и конфигурационный файл
passh doctor               # проверка настройки, только чтение
passh add work/github      # пароль (или сгенерировать), имя пользователя, url, теги, заметки
passh ls
passh show work/github
passh copy work/github     # пароль в буфер обмена, очищается через 30 с
passh                      # TUI: просмотр по папкам или тегам
```

`passh init` предлагает напечатать бумажный ключ восстановления. Сделайте это (см. [Бумажный ключ восстановления](#бумажный-ключ-восстановления)).

Переходите с `pass`? Выполните `passh import pass --dry-run`, затем `passh import pass`. gpg нужен только для этой команды, а хранилище pass только читается.

## Повседневные команды

```bash
passh unlock                         # по желанию: какое-то время без запроса фразы (15 мин простоя, не больше 2 ч)
passh ls [folder]                    # дерево; --tag t фильтрует по тегу
passh find github                    # нечёткий поиск по путям и тегам
passh tags                           # теги с количеством записей
passh show work/github --field username
passh copy work/github --field username
passh generate work/new-site 32 --symbols    # --force заменяет существующий пароль
passh edit work/github               # встроенная форма; --editor открывает $EDITOR (Linux)
passh mv work/jira work/atlassian/jira
passh rm work/old-site               # просит подтверждения
passh tag work/github --add rotate-soon --remove dev
passh lock                           # остановить агента сейчас
```

У каждой команды есть `--help`. Глобальные флаги: `--config <file>` и `--vault <file>` (другое хранилище, конфигурационный файл не нужен).

## На Raspberry Pi по SSH

Установите passh на Pi, как описано выше, от имени обычного пользователя, и храните хранилище там. Сервер настраивать не нужно: passh — просто команда, которую вы запускаете через `ssh`.

```bash
ssh -t pi passh                      # TUI; всему, что спрашивает ввод, нужен -t
ssh -t pi passh copy work/github     # попадает в ваш локальный буфер обмена через OSC 52
```

Чтобы передать секрет по конвейеру в локальную программу, один раз запустите агента с терминалом. После этого команды **без** `-t` работают, пока агент не завершится (15 мин без использования, не больше 2 ч), даже после окончания той SSH-сессии:

```bash
ssh -t pi passh unlock               # --ttl 30m для меньшего максимума
ssh pi passh show work/github --field password | pbcopy
ssh pi passh lock                    # готово: остановить агента
```

Не используйте `-t` при передаче по конвейеру и экспорте: терминал превращает переводы строк в CRLF и подмешивает сообщения об ошибках в данные. Разблокировка на Pi занимает несколько секунд (scrypt медленный намеренно); после неё команды работают быстро. См. [EXAMPLES.md §6](EXAMPLES.md#6-vault-on-a-server-eg-a-raspberry-pi).

## Копии и резервные копии

Хранилище (по умолчанию `~/.local/share/passh/vault.passh`) — один зашифрованный текстовый файл. Копируйте его чем угодно: `cp`, `scp`, флешка, облачная папка, почта. Затем проверьте копию:

```bash
passh backup /media/usb/                    # проверенная копия: записана, прочитана обратно, SHA-256 сравнён
passh verify /media/usb/vault-….passh       # структура и SHA-256, парольная фраза не нужна
passh verify --full /media/usb/vault-….passh  # ещё и расшифровывает: ревизия, дата, число записей
```

Побайтная копия имеет тот же SHA-256, что и оригинал. Копия, которую переформатировал почтовый клиент или которую вставили как текст, всё равно открывается.

**Автоматические резервные копии.** Перед каждым изменением passh сохраняет предыдущую версию в `~/.local/state/passh/backups/` (последние 10; `[backup] keep` в конфигурации). `passh backups` показывает их список. Чтобы вернуться к одной из них, скопируйте её поверх файла хранилища и выполните `passh verify --full`; passh один раз предупредит, что копия старее уже виденной: ответьте `y`. Эти копии защищают от ошибок, но не от потери диска, поэтому храните копии и в других местах.

**Переезд на новую машину:** скопируйте бинарник и файл хранилища, выполните `passh verify --full <file>`, затем запишите `vault = "<path>"` в `~/.config/passh/config.toml` или используйте `--vault`.

### Бумажный ключ восстановления

```bash
passh recovery-key print -o /dev/shm/recovery.txt   # текстовый лист; введите PRINT RECOVERY KEY
# напечатайте, затем:
rm /dev/shm/recovery.txt
passh recovery-key print --web                       # или: страница печати, с ключом в виде QR-кода
```

Если вы забудете парольную фразу, лист откроет любую копию хранилища, сделанную после последнего `rekey`: `passh recover` спрашивает ключ и задаёт новую парольную фразу. Тот, у кого есть лист и копия хранилища, может прочитать всё, поэтому храните лист офлайн, как наличные.

- `passh passwd` меняет парольную фразу; бумажный ключ остаётся действительным.
- `passh rekey` создаёт новый ключ хранилища: старая парольная фраза и старый бумажный ключ перестают открывать новые версии файла. Используйте его, если одно из них могло утечь, затем напечатайте новый лист. Старые копии и резервные копии по-прежнему открываются тем, что было действительно при их создании.

### Восстановление без passh

Стандартной утилитой `age` (v1.0 или новее) хранилище можно расшифровать на любой машине — парольной фразой или бумажным ключом. Шаги описаны в [spec.ru.md §8](spec.ru.md#8-резервное-копирование-и-восстановление), а также в [EXAMPLES.md §7.6](EXAMPLES.md#76-without-passh), который входит в архив релиза. ## Экспорт и печать

Экспорт нужен для перехода на другую программу. Для резервной копии копируйте файл хранилища.

```bash
passh export --format bitwarden-json --age age1… -o vault.json.age   # зашифровано на ключ age
passh export --format csv -o /dev/shm/vault.csv                      # открытый текст: введите EXPORT PLAINTEXT
ssh pi passh export --format csv --confirm-plaintext > vault.csv     # по SSH: без -t, нужен агент
passh print -o /dev/shm/sheet.txt                                    # текстовый лист с паролями; удалите после печати
passh print --web                                                    # одноразовая страница печати для браузера в LAN/VPN
```

Форматы: `csv`, `json`, `bitwarden-json`. Фильтры: `--tag`, `--folder`; `print` также принимает `--fields`. passh печатает простой текст; для PDF используйте страницу печати и «Сохранить как PDF» в браузере. Экспортированные данные никогда не выводятся в терминал. `--spreadsheet-safe` защищает CSV от формул в электронных таблицах, но меняет значения, поэтому не импортируйте такой файл в менеджер паролей.

Странице печати нужно `[print_web] enabled = true` в конфигурации. passh показывает URL, QR-код и отпечаток сертификата. При первом заходе с устройства браузер предупредит о сертификате: принимайте его, только если SHA-256-отпечаток совпадает с тем, что показывает passh. Страница отдаётся один раз и останавливается через 5 минут. В TUI клавиша `P` сначала спрашивает, какие записи и поля печатать. См. [EXAMPLES.md §9](EXAMPLES.md#9-printing).

## Удаление

```bash
passh lock                                       # остановить агента, если он запущен
rm ~/.local/bin/passh
rm -r ~/.config/passh ~/.local/state/passh       # в папке состояния лежат автоматические резервные копии: их можно оставить
```

Файл хранилища остаётся на месте.

## Безопасность

- **Используйте сильную парольную фразу: 6 или больше случайных слов.** Украденную копию хранилища можно атаковать офлайн, и парольная фраза — её главная защита. passh предупреждает о слабых фразах, но не отказывает.
- **Исключите терминал из истории буфера обмена.** passh очищает буфер через 30 с, но программы с историей могли уже сохранить пароль: Universal Clipboard в macOS (отправляет буфер на другие ваши устройства Apple), история и синхронизация буфера в Android, менеджеры буфера обмена. Исключите в них терминал или отключите их. Если сессия закончится раньше таймаута (например, оборвётся SSH-соединение), буфер не очистится.
- **Напечатанные файлы — открытый текст.** Текстовый лист или PDF, сохранённый браузером со страницы печати, оставленные в «Загрузках» или где-либо на диске, — копия ваших паролей. В Linux пишите его в `/dev/shm` через `-o` (passh предупреждает, если файл не на tmpfs); напечатайте и удалите. То же относится к экспорту в открытом виде.
- **После страницы печати закройте вкладку.** Браузер может сохранить страницу для восстановления сессии, а «Сохранить как PDF» или очередь печати могут оставить файлы. Не вставляйте URL в мессенджер: его предпросмотр ссылки израсходует одноразовую страницу.
- **Swap может хранить память.** passh не блокирует свою память, поэтому расшифрованные данные могут попасть в swap. `passh doctor` предупреждает, если swap включён; отключить или зашифровать его — на ваше усмотрение.
- **Храните бумажный ключ офлайн.** Вместе с любой копией хранилища, сделанной до следующего `passh rekey`, он даёт полный доступ. Если лист потерян, выполните `passh rekey`.
- **Вне рамок** ([spec.ru.md §9](spec.ru.md#9-модель-угроз)): passh не защищает от того, кто может действовать от имени вашей учётной записи, в том числе с украденным SSH-ключом к ней. У такого атакующего полный доступ, пока разблокированы TUI или агент (любой процесс вашего пользователя может запросить у агента ключ хранилища), и он может поставить кейлоггер. Другие ограничения: размер хранилища виден; подложенная старая действительная копия замечается только на машине, которая видела более новую; копии, сделанные до `rekey`, по-прежнему открываются старой фразой или бумажным ключом; `show --raw` выводит содержимое записи без экранирования.

## Сборка из исходников

Нужен Go 1.26 или новее. У passh нет зависимостей на C, поэтому любая машина может собрать его для любой платформы. Например, для Raspberry Pi на ноутбуке:

```bash
# Pi 3/4/5 или Zero 2 W с 64-битной ОС (`uname -m` на Pi выводит aarch64)
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o passh-linux-arm64 ./cmd/passh

# те же Pi с 32-битной ОС (armv7l)
CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build -trimpath -ldflags "-s -w" -o passh-linux-armv7 ./cmd/passh

scp passh-linux-arm64 pi:.local/bin/passh
```

Pi 1 и Pi Zero/Zero W (armv6l) нужен `GOARM=6`; этой платформы нет в официальном релизе. Тесты запускаются командой `go test ./...`.
