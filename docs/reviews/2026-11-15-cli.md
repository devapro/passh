### CLI-001 · high · OUT-1 · CONFIRMED

`internal/cli/printcmd.go:327`

**What:** `recovery-key print` without `-o` writes the sheet to stdout (`a.write`, line 57–60), then prints `Wrote the paper recovery key to stdout.` with `a.printf`, which is also stdout. The redirected PDF or text sheet ends with that line.

**Proof** (scratch binary, isolated env, pty as controlling terminal, stdout redirected to a file):

```
TAIL of redirected sheet: b'-----------…-----\nWrote the paper recovery key to stdout.\n'
```

**Why it matters:** the help text of the command says "use -o file or redirect stdout". The redirected PDF carries bytes after `%%EOF`, and the text sheet a stray line. `passh print` does this correctly with `a.notef` (stderr, line 229). The existing test (`cmd/passh/print_test.go:124–139`) only covers `-o`.

**Fix:** use `a.notef` at line 327 (and at 406 for symmetry). Add a black-box test with `sessOpts{pipeStdout: true}` that compares stdout with the `-o` file byte for byte.

**Effort:** S.

### CLI-002 · medium · ERR-4, INV-6 (S6) · CONFIRMED

`internal/cli/copy.go:70`, `internal/cli/doctor.go:371`; the text comes from `internal/clipboard/clipboard.go:427–429`.

**What:** both callers treat an interrupted wait as "cleared" when `errors.Is(err, clipboard.ErrInterrupted) && !strings.Contains(err.Error(), "failed")`.

**Why it matters:** it is right today: the failure branch always says "clearing the clipboard failed", and the success branch's `why` is a signal name or a context cause without that word. A wording change, or a context cause that contains "failed", flips `copy` to "Clipboard cleared." with exit 0 when it wasn't, or the reverse.

**Fix:** in `internal/clipboard` add `var ErrClearFailed = errors.New("clearing the clipboard failed")` and build line 427 as `fmt.Errorf("%w (%s): %w: %w", ErrInterrupted, why, ErrClearFailed, err)`. Callers test `errors.Is(err, clipboard.ErrClearFailed)`. Add a test with a clipboard command that fails on the clear.

**Effort:** S.

### CLI-003 · medium · FILE-2 · CONFIRMED

`internal/cli/files.go:247–285` (`writeChecked`)

**What:** `backup <dest>` creates the destination with `O_CREATE|O_EXCL` under its final name, then writes, fsyncs, closes and reads it back. FILE-2 names `backup <dest>` among the files that must be complete or absent after a crash: temporary file in the same folder, fsync, read-back, rename, folder fsync.

**Why it matters:** a power loss or `kill -9` between create and the read-back leaves a short file called `vault-<time>.passh` on the backup medium. `passh verify` catches it, but only if the user runs it; the folder fsync is also best effort. The cleanup on failure has its own gap (CLI-006).

**Fix:** write to `.<name>.tmp-<random>` in the destination folder (0600, `O_EXCL`), fsync, read back and compare, then move into place without replacing (`link` + `unlink`, or the `renameNoReplace` that `internal/vault` already has), then fsync the folder. The simplest home is an exported `vault.WriteCopy(dest, content)`, which also keeps INV-11's check (rename only in `internal/vault`) true; see "Rules" below.

**Effort:** M.

### CLI-004 · medium · OUT-6, CONC-1, CONC-6 · CONFIRMED

`internal/tty/tty.go:118–183` (`ReadPassphrase`); also `ReadLine`, `YesNo`, `Confirm`, `NewPassphrase`.

**What:** raw mode is restored by a `defer`, which covers return, error and Ctrl-C (a key in raw mode). A SIGTERM or SIGHUP during the prompt kills the process with the default action, and the defer never runs. No prompt function takes a `ctx`, so nothing can cancel a prompt either.

**Proof** (pty, `passh ls`, SIGTERM at `Passphrase:`):

```
SIGTERM rc -15 ECHO during prompt: False ICANON: False | after exit ECHO: False ICANON: False
```

**Why it matters:** OUT-6 lists signals explicitly. After `kill <pid>` or `pkill passh` at a prompt (a wrapper script's timeout does the same), the shell has no echo until `stty sane` or `reset`. For SIGHUP the terminal is usually gone, so SIGTERM is the practical case.

**Fix:** give the prompts a context: `ReadPassphrase(ctx, prompt)`. Inside, `signal.Notify` for SIGTERM and SIGHUP on a buffered channel with `defer signal.Stop`, and `context.AfterFunc` (or the signal) calling `t.f.SetReadDeadline(time.Now())` to unblock the read; then restore and return an error. `/dev/tty` supports deadlines on Linux; on macOS it doesn't (kqueue), so there the fallback is to restore the terminal from the signal goroutine and re-raise the signal. Add a pty test that sends SIGTERM and checks ECHO afterwards.

**Effort:** M.

### CLI-005 · medium · SEC-1 · CONFIRMED

`internal/cli/session.go:398–429` (`readRecoveryKey`), `internal/tty/tty.go:249–281` (`ReadLine`)

**What:** `passh recover` reads the vault key (`AGE-SECRET-KEY-1…`) with echo on, through `ReadLine`, which returns a `string`; the lines are collected in a `strings.Builder` and passed to `keys.ParseRecoveryKey(string)`. Nothing can be wiped, and the typed key stays on screen and in the scrollback (terminal, tmux, an SSH client's log).

**Why it matters:** SEC-1 names "vault key text" as `[]byte`, wiped. The key is the one secret that stays valid until `rekey`. The echo is a deliberate choice (comment at 393–397: typos are easy to spot), but the exposure afterwards isn't handled: there is no erase and no advice.

**Fix:** add `tty.ReadLineBytes` (same loop, returns the `[]byte`), collect into a `[]byte` and `clear` it; give `keys` a `[]byte` parser (cross-package). After a successful parse, erase the typed lines (`ESC[<n>A ESC[J`) and say that the scrollback may still hold the key, or recommend `passh rekey` when the terminal was shared or logged.

**Effort:** M.

### CLI-006 · medium · ERR-1, FILE-5 · CONFIRMED

`internal/cli/exportcmd.go:129–133,144` (`writeNewFile`), `internal/cli/files.go:256–260,275,280` (`writeChecked`)

**What:** the failure paths call `f.Close()` and `os.Remove(path)` and drop both errors (golangci-lint errcheck reports the five `os.Remove` calls). `writeChecked` then returns "…; the copy was removed" whether or not it was.

**Why it matters:** `writeNewFile` writes plaintext exports, password sheets and the recovery key. If the write fails halfway (disk full) and the removal fails too (read-only remount, the file made immutable, a network file system), a partial plaintext file stays behind and the message doesn't say so. FILE-5 asks for the removal error to be checked where the file holds plaintext.

**Fix:** `if rerr := os.Remove(path); rerr != nil { err = fmt.Errorf("%w; the partial file %s could not be removed: %v", err, display, rerr) }`, and only say "the copy was removed" when it was. `_ = f.Close()` with a comment (the write error is the one reported). The two functions are near copies; fix them once (see "Structure").

**Effort:** S.

### CLI-007 · medium · TEST-7, TEST-13 · CONFIRMED

`cmd/passh/copyedit_test.go:138–139` (`TestEditForm`); related: `cmd/passh/tui_test.go:38`

**What:** the test types `newbie` and then waits for the contiguous text `newbie` in the raw pty output. Bubble Tea redraws per key with cursor and style sequences, so when the keys arrive in separate reads the output is `new␛[7m ␛[m␛[Kbie` and the wait times out after 45 s.

**Evidence:** one failure in six runs of `go test -race -count=1 -shuffle=on ./cmd/...` (load average about 12 because other reviewers ran tests at the same time). I did not save that run's full log; the terminal dump in its tail showed the edit form with `username  new▮bie`, and `TestEditForm` is the only test that types that text. Four further runs (`-count=4`) passed. `tui_test.go:38` has a bare `time.Sleep(100 * time.Millisecond)` before `ctrl+s`, without a comment, which looks like a workaround for the same kind of timing.

**Why it matters:** a red test that isn't a product bug, on exactly the loaded machines where CI runs.

**Fix:** don't match typed text in a diff renderer's byte stream. Send the keys and `ctrl+s` without the intermediate wait and assert on the saved value (the test already does at line 144), or give the harness a small screen model (apply cursor moves and erases to a grid) and match on the grid. Replace the sleep in `tui_test.go` with a wait on a stable marker.

**Effort:** S (drop the wait) or M (screen model).

### CLI-008 · medium · TEST-7, CONC-8 · CONFIRMED by reading

`internal/agent/server_test.go:240,247,305`; `internal/agent/start_test.go:131,316,465`; `internal/tty/tty_test.go:110`; production: `internal/agent/server.go` and `internal/clipboard/clipboard.go` call `time.Now` directly.

**What:** TTL tests use real time with small margins. `TestIdleTTL` keeps a 200 ms idle TTL alive by sleeping 40 ms between key requests, so one 200 ms stall of the test process fails it. Several tests sleep a fixed time and then assert that something did *not* happen (`start_test.go:131,316,465`), which can only pass, never detect, when the machine is slow. `console.rest()` sleeps 50 ms and assumes the output has stopped growing. None of these has the comment TEST-7 asks for.

**Why it matters:** flakiness under `-race` and load, and negative assertions that prove little. I saw no failure in three runs.

**Fix:** give `server` a `now func() time.Time` and a timer factory, and `Clipboard` the same (CONC-8); test idle and max TTL with a fake clock. `testing/synctest` won't do here, because these tests use real sockets and processes. For the negative checks, poll for a positive signal instead (for SIGHUP: a `Status` round trip after the signal). Comment the sleeps that really are "time passing under test" (`cmd/passh/e2e_test.go:321`).

**Effort:** M.

### CLI-009 · low · OUT-1 · CONFIRMED

`internal/cli/cli.go:148` (`printf`), 31 call sites; e.g. `edit.go:58,213–215`, `session.go:79,156,235`, `copy.go:63,68`.

**What:** confirmations and hints ("Saved x.", "Copied the password…", "Show it with: …", "Unlocked …") go to stdout. Others go to stderr through `notef` ("exported …", "printed …", "no tags"). Proof: `passh generate work/x > out` leaves both message lines in `out`.

**Why it matters:** OUT-1 says stdout is data only and hints go to stderr. For commands that produce no data the harm is small, but the split is arbitrary, and CLI-001 is the case where it bites. The black-box tests assert these messages on stdout (`e2e_test.go:204`), so changing it is a visible behaviour change.

**Fix:** decide once (see "Rules"): either all human messages go to stderr (`notef`), or OUT-1 says that commands without data output may confirm on stdout. Then make `printf` unavailable to commands that also write data.

**Effort:** M (many tests assert the stream).

### CLI-014 · low · CONC-3, CONC-4 · CONFIRMED

### CLI-015 · low · INV-5 · CONFIRMED, no exploit found

`TTY.Printf` (`internal/tty/tty.go:105`) writes unescaped. Most callers pass constants or `line(…)`/`displayPath(…)`; these pass raw values: `printcmd.go:389` (`%v` of an error holding the path the user just typed), `edit.go:99` (tag error), `session.go:427` (recovery key error), `printcmd.go:455` (URL built from `print_web.hostnames`). All of it is typed by the user or comes from their own config, so nothing hostile reaches the terminal today. INV-5's check ("trace each `t.Printf` argument to a sanitize call") fails for them. **Fix:** make `TTY.Printf` escape its formatted result with `sanitize.Text` (as `warnf` does) and add a `TTY.WriteRaw` for the few callers that send control sequences (`printcmd.go:460,509,526`). `tty` is a leaf (API-2), so either allow `tty → sanitize` or wrap in `cli`. Effort S.

### CLI-016 · low · SEC-1 · CONFIRMED

`internal/clipboard/clipboard.go:235`: `c.term.Write(OSC52(value))` leaves the sequence (base64 of the password) in an unwiped buffer. **Fix:** `seq := OSC52(value); defer clear(seq)`. Effort S.

### CLI-017 · low · robustness of the passphrase prompt · CONFIRMED by reading

`internal/tty/tty.go:173–180`: control bytes below 0x20 are ignored, so of an arrow key (`ESC [ A`) the `ESC` is dropped and `[A` is appended to the passphrase, invisibly because echo is off. The result is a "wrong passphrase", or at `New passphrase` a passphrase the user doesn't know they typed if the slip repeats. **Fix:** on `ESC`, swallow the rest of a CSI/SS3 sequence (bytes up to a final byte in 0x40–0x7e). Add a test case to `TestReadPassphraseEditing`. Effort S.

### CLI-018 · low · spec §5.4 question · SUSPECTED (design)

`internal/cli/session.go:284,322` and `printcmd.go:339` open the vault through the usual chain, so with a running agent `passwd`, `rekey` and `recovery-key print` never ask for the current passphrase (`e2e_test.go:222–230` tests this for `rekey`). Anyone at an unlocked session can change the passphrase, invalidate the paper key, or take a copy of the vault key that stays valid for later versions of the file. The spec doesn't say either way. **Suggested:** the owner decides; if these three should always ask, pass `openOpts{noAgent: true}` as `unlock` does. Effort S.

### CLI-019 · low · OUT-3, §4.9 · CONFIRMED

`internal/importpass/gpg.go:75` looks for a terminal on `os.Stdin`, `os.Stderr`, `os.Stdout`. OUT-3 keeps those to `main`, `cli.Main` and the agent child. It also misses a case: `passh import pass > log 2>&1 < /dev/null` in a terminal has `/dev/tty` but none of the three, so `GPG_TTY` isn't set and a curses pinentry fails. **Fix:** the CLI fills `Options.GPG.TTY` from its `*tty.TTY` (export `importpass.TerminalName(f)` or move it to `tty`), and `importpass` stops reading the globals. Effort S.

### CLI-020 · low · TEST-12 · CONFIRMED

## Rules that look wrong or impractical for this codebase

- **OUT-1** doesn't say where a confirmation goes for a command that produces no data ("Saved x.", "Locked: …"). The code and 20-odd test assertions put them on stdout; the rule's wording ("hints … go to stderr") puts them on stderr. State it either way; CLI-009 depends on it.
- **FILE-2 against INV-11's check.** FILE-2 wants `backup <dest>` written with a temporary file and a rename; INV-11's check says `os.Rename`/`renameNoReplace` appear only in `internal/vault`. Both hold only if the backup writer moves into `internal/vault`. Say so in FILE-2.
- **CONC-1 for prompts.** "Return promptly when ctx is cancelled" can't be done portably for a blocking read on `/dev/tty` (no deadlines on macOS). The rule should name the mechanism it expects (deadline where supported, signal handling plus restore elsewhere), or exempt `internal/tty` with OUT-6 as the binding rule.
- **TEST-7 and `testing/synctest`.** The agent and clipboard tests use real sockets, pipes, signals and child processes, where synctest doesn't apply. For them the workable rule is CONC-8 (inject the clock), which is only a SHOULD.
- **INV-12 "key-block hash checked"** doesn't match the protocol, which allows a key request without a hash (CLI-013). Tighten the code or the rule.
- **FILE-3** depends on review alone: `.golangci.yml` excludes `(*os.File).Close` from errcheck, so the `f.Close()` calls in write paths (`files.go:257`, `exportcmd.go:130`) are invisible to the linter. A short custom check (grep for `Close()` inside functions that open with `O_WRONLY`) would help.

## Structural observations

- **`internal/cli/printcmd.go` (549 lines) holds four things.** Suggested split: `output.go` (`output`, `prepareOutput`, `write`, plus `writeNewFile` from `exportcmd.go`); `printcmd.go` (`print`); `recoverykey.go` (`recovery-key print`, `offerRecoverySheet`, `defaultSheetPath`); `printpage.go` (`servePrintPage`, `printPageKeys`: 125 lines of raw-mode key loop, countdown and clipboard handling that is a small TUI of its own).
- **`internal/cli/session.go` (429 lines)** mixes `init`, the agent commands and the passphrase commands. Split into `initcmd.go`, `agentcmd.go` (`unlock`, `lock`, `stopAgent`, `agentTimes`, `fmtDuration`) and `passphrase.go` (`passwd`, `rekey`, `recover`, `readRecoveryKey`).
- **Two near-identical file writers:** `writeChecked` (`files.go:247`) and `writeNewFile` (`exportcmd.go:121`): `O_EXCL` create, chmod, write, sync, close, remove on failure. One helper with an optional read-back fixes CLI-003 and CLI-006 in one place.
- **Duplicated logic:** `shellQuote` in `cli/edit.go:226` and `clipboard/clipboard.go:125`, with different safe sets (`%` only in clipboard); the "interrupted" translation three times (CLI-021); the plaintext confirmation flow in `exportcmd.go:66–79` and `printcmd.go:205–215`; tag normalising loops in `entries.go:33`, `printcmd.go:174` and `export.ParseFilter`.
- **Long functions:** `checkVaultFile` (`doctor.go:143–223`, five independent checks), `printPageKeys` (78 lines), and the `RunE` closures of `export` (72 lines), `print` (72) and `unlock` (50). Moving each closure body into a named method (`func (a *app) runExport(ctx, opts) error`) would make them testable without cobra.
- **`app` holds `*os.File` streams** (`cli.go:50–52`), so unit tests can't capture output; `internal/cli` has 9 test functions for about 3,700 lines, and nearly all coverage is black-box in `cmd/passh` (slow: a build plus scrypt per test). `io.Writer` fields plus an `isTerminal func() bool` would allow fast unit tests of the command bodies, and would have caught CLI-001.
- **`doctor`** threads no context and builds its own `agent.Client` and clipboard; with a ctx field (an object that lives for one operation, which CONC-1 allows) the two `context.Background()` calls go away.
