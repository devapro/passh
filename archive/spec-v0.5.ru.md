## 1. Краткое описание

passh — это один бинарный файл на Go для управления паролями в **совместимом с pass** хранилище: файлы, зашифрованные GPG, лежат в папке, которая может быть git-репозиторием. Вы устанавливаете один файл, указываете в конфигурационном файле путь к хранилищу и запускаете `passh`, как любую другую команду. Он работает там, где находятся хранилище и ваш ключ GPG: на ноутбуке или на сервере, к которому вы подключаетесь обычным `ssh`.

Поверх `pass` он добавляет:

- TUI для просмотра по папкам (категориям) и тегам;
- теги с зашифрованным индексом, чтобы для вывода списка по тегу не приходилось расшифровывать каждую запись;
- копирование в буфер обмена, в том числе по SSH (OSC 52), с очисткой по тайм-ауту;
- блокировку после периода бездействия;
- экспорт (CSV / JSON / Bitwarden JSON / архив) и печать (PDF / текст, а также одноразовая страница печати, которая открывается в браузере в LAN или VPN).

## 2. Цели и что не входит в цели

### Цели

| # | Цель |
|---|------|
| G1 | Один статический бинарный файл на Go для `linux/amd64`, `linux/arm64`, `linux/arm/v7`, `darwin/amd64` и `darwin/arm64` |
| G2 | Вся установка: скопировать бинарный файл и написать конфигурационный файл с путём к хранилищу. Без root, без демона, без изменений в системе (§3.2) |
| G3 | Совместимость с `pass`: существующие хранилища открываются без изменений, а `pass` продолжает работать с хранилищем passh |
| G4 | Одинаковая работа локально и по SSH |
| G5 | Просмотр и поиск по папкам и по тегам в TUI |
| G6 | Экспорт и печать для миграции и бумажной резервной копии, включая печать из браузера без сохранения файла |

### Что не входит в цели (v1)

- Расширения для браузеров, автозаполнение на мобильных устройствах, нативные мобильные приложения
- Совместный доступ нескольких пользователей, роли, права для отдельных устройств
- Веб-интерфейс или HTTP API. Единственное исключение — одноразовая страница печати (§7.4)
- Режим сервера или демона, настройка SSH, контейнеры
- Защита от подмены сверх того, что даёт `pass` (нет подписанной истории, нет закрепления получателей)
- Защита от атакующего, который контролирует вашу учётную запись
- Windows

## 3. Установка и настройка

### 3.1 Установка

Скопируйте бинарный файл `passh` в папку из вашего `PATH`, например в `~/.local/bin`.

Требования во время выполнения те же, что у `pass`:

- `gpg` (GnuPG ≥ 2.2) с агентом и pinentry;
- `git`, только если хранилище является git-репозиторием.

### 3.2 След в системе

passh **не меняет систему**. Он пишет только в эти места:

| Путь | Что passh туда пишет |
|---|---|
| Хранилище (`store` в конфигурации) | Записи, `.passh/tags.idx.gpg` и коммиты git, если хранилище является git-репозиторием |
| Конфигурационный файл (§3.3) | Создаётся командой `passh init`, только если его нет; после этого никогда не перезаписывается |
| `$XDG_STATE_HOME/passh/` (по умолчанию `~/.local/state/passh/`) | Сертификат и ключ страницы печати (§7.4) и файл блокировки |
| Временная папка на tmpfs | Только для `edit --editor` (§5.4); после использования удаляется |

passh никогда:

- не требует root;
- не пишет в системные файлы и в файлы других пользователей;
- не меняет `gpg.conf`, `gpg-agent.conf`, глобальную конфигурацию git и файлы запуска shell;
- не устанавливает службы, задания cron и фоновые процессы, которые продолжают работать после завершения команды (сервер страницы печати работает внутри процесса passh);
- не трогает настройки брандмауэра, swap и SSH;
- ничего не устанавливает в хранилища сертификатов ОС или браузера.

**Влияние на gpg-agent во время работы:** при блокировке passh просит агента забыть кешированную парольную фразу только для ключей хранилища (§5.2). Другие кешированные ключи не затрагиваются.

**Удаление:** удалите бинарный файл, конфигурационный файл и `~/.local/state/passh/`. Хранилище остаётся обычным хранилищем pass.

### 3.3 Конфигурационный файл

Расположение (используется первый найденный вариант):

1. `--config <file>`;
2. `$PASSH_CONFIG`;
3. `$XDG_CONFIG_HOME/passh/config.toml` (по умолчанию `~/.config/passh/config.toml`).

Обязателен только `store`:

```toml
store = "~/.password-store"

[session]
idle_ttl    = "5m"      # TUI locks after this much inactivity
clear_agent = true      # on lock, make gpg-agent forget the store key's passphrase

[clipboard]
clear_after = "30s"
osc52       = true      # copy through the terminal (works over SSH)
command     = []        # optional local tool instead, e.g. ["pbcopy"] or ["wl-copy"]

[git]
auto_commit = true      # commit every change if the store is a git repo

[print_web]             # §7.4; off unless enabled
enabled    = false
port       = 8443
interfaces = ["wg0", "eth0"]
allow_from = []         # extra CIDR limit; default = subnets of the bound addresses
hostnames  = []         # optional names for the certificate, e.g. ["pi.local"]
ttl        = "5m"       # 1–15 min

[gpg]
binary = ""             # default: gpg from PATH
```

- `--store <dir>` переопределяет `store` для одной команды.
- Если конфигурационного файла нет, passh выводит подсказку, как его создать (`passh init`).
- Неизвестные ключи считаются ошибкой, чтобы опечатки не оставались незамеченными.

## 4. Хранение

### 4.1 Структура (совместимая с pass)

```
~/.password-store/
├── .gpg-id                 # recipient key(s), as in pass
├── .git/                   # optional
├── .passh/                 # passh-specific data; ignored by pass
│   └── tags.idx.gpg        # encrypted tag index (§4.3)
├── work/
│   ├── jira.gpg
│   └── github.gpg
└── bank/
    └── revolut.gpg
```

- **Папки = категории**, как в pass.
- Получатели берутся из `.gpg-id` по правилам pass, включая файлы `.gpg-id` во вложенных папках.
- Имена файлов и пути **не шифруются**, как в pass.

### 4.2 Формат записи

Как в соглашении pass. Строка 1 — пароль, за ней идут метаданные `key: value`, затем произвольные заметки.

```
s3cr3t-P@ss
username: arsenii
url: https://github.com
tags: work, dev, 2fa
---
Free-form notes. Recovery codes, etc.
```

- Метаданные — это идущие подряд строки `key: value` сразу после строки 1. Они заканчиваются на строке `---` или на первой строке, которая не подходит под этот формат. Всё, что идёт дальше, — заметки.
- Зарезервированные ключи: `username`, `url`, `tags`, `otp` (зарезервирован, в v1 не реализован). Значения `otp:` и строки `otpauth://` маскируются так же, как пароли.
- Неизвестные и повторяющиеся ключи сохраняются в исходном порядке.
- Запись, которую passh только читает, никогда не перезаписывается. При редактировании перезаписываются только изменённые строки.

### 4.3 Теги

- passh ведёт `.passh/tags.idx.gpg` — зашифрованный словарь `{path → [tags]}`, зашифрованный для получателей хранилища.
- Он расшифровывается один раз после разблокировки и хранится в памяти.
- passh обновляет его при каждом добавлении, редактировании, перемещении или удалении.
- `passh reindex` перестраивает его после правок, сделанных обычным `pass`.
- Индекс хранит хеш, вычисленный по списку путей записей и хешам файлов. Если хеш перестаёт совпадать, TUI показывает «tag index stale — run reindex».

### 4.4 Git

- Если хранилище является git-репозиторием и включён `git.auto_commit`, каждое изменение фиксируется коммитом. Сообщение коммита содержит только действие и путь.
- passh запускает git с собственными настройками репозитория хранилища. Если личность автора не настроена, он передаёт `passh <passh@localhost>` только для этого коммита и поэтому никогда не меняет конфигурацию git.
- `passh sync` выполняет `git pull --ff-only`, затем `git push` с вышестоящей веткой (upstream), настроенной в репозитории.
- Коммиты не подписываются и не проверяются. История заслуживает доверия ровно настолько, насколько ему заслуживает удалённый репозиторий (§9).
- Сквозного вызова git нет; запускайте `git -C <store> …` сами.

### 4.5 Правила для путей

Каждый путь, полученный от пользователя или с диска, проходит через один валидатор:

- путь относительный к корню хранилища, без сегментов `..` и не абсолютный;
- ни один сегмент не начинается с `-` или `.`;
- нет управляющих символов.

Файлы открываются через `os.Root` (Go ≥ 1.24), поэтому символические ссылки не могут вести за пределы хранилища.

## 5. Сессия и безопасность

### 5.1 Разблокировка

- Для расшифровки используются `gpg`, а также gpg-agent и pinentry пользователя, точно так же, как в `pass` (ADR-1).
- passh задаёт `GPG_TTY` для своих вызовов gpg, чтобы pinentry запрашивал ввод в текущем терминале, в том числе по SSH.
- passh не меняет настройки агента. `doctor` выводит предупреждение о длинных TTL кеша агента, ничего не меняя.

### 5.2 Блокировка

TUI блокируется, когда:

- пользователь нажимает `L` или запускает `passh lock`;
- TUI завершается;
- TUI бездействует в течение `session.idle_ttl`;
- passh получает SIGHUP, SIGTERM или SIGINT, например при обрыве SSH-соединения.

При блокировке passh:

- стирает из своей памяти расшифрованные записи и индекс тегов;
- если включён `session.clear_agent`, просит gpg-agent забыть кешированную парольную фразу только для ключей хранилища (`CLEAR_PASSPHRASE --mode=normal <keygrip>`).

Команды вне TUI полагаются на собственные TTL кеша агента.

### 5.3 Встроенные правила безопасности

Они не требуют настройки и не затрагивают систему:

| Правило | Подробности |
|---|---|
| S1 | passh никогда не записывает открытый текст на постоянный диск. `edit --editor` использует временный файл на tmpfs (`$XDG_RUNTIME_DIR` или `/dev/shm`) с правами 0600 и затем удаляет его. Если tmpfs нет (например, в macOS), `edit --editor` отклоняется и используется встроенная форма |
| S2 | Открытый текст передаётся в `gpg --encrypt` через stdin, но никогда — как аргумент или переменная окружения |
| S3 | Для генерации паролей используется `crypto/rand` с выборкой с отклонением (rejection sampling, без смещения по модулю). Длина по умолчанию 24, алфавит настраивается |
| S4 | При выводе в терминал управляющие символы и escape-последовательности из содержимого записей экранируются, поэтому запись не может управлять вашим терминалом, например внедрив запись в буфер обмена через OSC 52. `show --raw` выводит байты как есть |
| S5 | В TUI пароли скрыты маской фиксированной длины; показанный пароль снова скрывается через 10 с |
| S6 | Буфер обмена очищается через `clipboard.clear_after`, если сессия ещё жива (по мере возможности) |
| S7 | Дампы памяти (core dumps) отключены для процесса passh (`setrlimit`), и это затрагивает только сам passh |
| S8 | Внешние программы (gpg, git, `$EDITOR`, команда буфера обмена) запускаются без shell, со списками аргументов и с `--` перед путями. Результаты gpg читаются из `--status-fd`, а не из вывода, предназначенного для человека |

Намеренно не предусмотрено (ADR-4):

- заблокированная или невыгружаемая память: `doctor` предупреждает, если swap включён;
- подписанная история или обнаружение подмены;
- закрепление получателей.

### 5.4 Редактирование

- `passh edit <path>` открывает встроенную форму: отдельные поля для пароля, имени пользователя, url и тегов и текстовую область для заметок. Однострочные поля не принимают переводы строк.
- `passh edit --editor <path>` использует `$EDITOR`, разбитый на слова без shell, и временный файл по правилу S1. Для известных редакторов passh добавляет флаги, защищающие от утечек:
  - vim: `-n -u NONE -i NONE -c "set nobackup nowritebackup noundofile noswapfile"`;
  - neovim: `-n --clean -i NONE -c "set nobackup nowritebackup noundofile noswapfile"`;
  - nano: `--ignorercfiles --nohelp`.

  Для остальных редакторов выводится предупреждение, что passh не может контролировать их файлы резервных копий.

## 6. Интерфейсы

### 6.1 CLI

Запуск `passh` без аргументов открывает TUI.

| Команда | Описание |
|---|---|
| `passh init <gpg-id>… [--store dir] [--git]` | Создать хранилище (как `pass init`) и записать конфигурационный файл, если его нет. Для существующего хранилища pass нужен только конфигурационный файл |
| `passh ls [folder] [--tag t]` | Вывести дерево, при необходимости с фильтром по тегу |
| `passh find <query>` | Нечёткий поиск по путям, а если хранилище разблокировано, то и по тегам |
| `passh show <path> [--field f] [--raw]` | Вывести запись или одно поле |
| `passh copy <path> [--field f]` | Скопировать в буфер обмена (§6.3) |
| `passh add <path> [--force]` | Интерактивное добавление: пароль (или генерация), имя пользователя, url, теги, заметки |
| `passh generate <path> [len] [--symbols] [--force]` | Сгенерировать и сохранить пароль |
| `passh edit <path> [--editor]` | Встроенная форма или `$EDITOR` (§5.4) |
| `passh mv <src> <dst>` / `passh rm <path>` | Переместить или удалить; обновляет индекс тегов |
| `passh tag <path> --add a --remove b` / `passh tags` | Изменить теги / вывести список тегов с количеством записей |
| `passh reindex` | Перестроить индекс тегов |
| `passh sync` | `git pull --ff-only`, затем `git push` |
| `passh export …` / `passh print …` | §7 |
| `passh unlock` | Запросить парольную фразу сейчас, чтобы последующие команды без терминала могли расшифровывать. Как долго — решает TTL кеша агента |
| `passh lock` | Сразу заставить gpg-agent забыть парольную фразу ключа хранилища |
| `passh doctor` | Проверить gpg, pinentry, TTL агента, git, swap, поддержку буфера обмена в терминале и конфигурацию. Только чтение: сообщает о проблемах, но никогда их не исправляет |

Глобальные флаги: `--config <file>`, `--store <dir>`.

### 6.2 TUI

Построен на Bubble Tea + Bubbles + Lip Gloss (charmbracelet).

```
┌ passh ── 🔓 unlocked · locks in 4:12 ────────────────────────────┐
│ VIEW: [Folders]  Tags                     / search_              │
├──────────────────────┬───────────────────────────────────────────┤
│ ▸ bank          (3)  │ work/github                               │
│ ▾ work          (12) │ username  arsenii                         │
│     github           │ password  ••••••••       [c]opy [r]eveal  │
│     jira             │ url       https://github.com              │
│     confluence       │ tags      work · dev · 2fa                │
│ ▸ homelab       (7)  │ notes     Recovery codes in notes…        │
├──────────────────────┴───────────────────────────────────────────┤
│ c copy pw · u copy user · r reveal · e edit · a add · t tags     │
│ Tab folders/tags · / search · P print · L lock · ? help · q quit │
└──────────────────────────────────────────────────────────────────┘
```

- **Два представления**, переключаются клавишей `Tab`:
  - *Folders* (папки): сворачиваемое дерево, повторяющее структуру каталогов;
  - *Tags* (теги): список тегов с количеством записей; при выборе тегов показываются их записи (логическое И).
- `/` открывает нечёткий поиск по путям и тегам.
- Панель подробностей расшифровывает только выбранную запись и только в момент выбора (с задержкой debounce 150 мс).
- `d` удаляет запись, а `P` открывает страницу печати (§7.4). Разрушительные действия требуют подтверждения.
- В узких терминалах (уже 80 столбцов, например на телефонах) используется одна панель: список → Enter → подробности → Esc.
- Все значения выводятся с учётом S4.

### 6.3 Буфер обмена

- **OSC 52** (`clipboard.osc52`): passh записывает значение через терминал (`ESC ] 52 ; c ; <base64> BEL`). Это работает локально и по SSH в терминалах с такой поддержкой: iTerm2, kitty, WezTerm, Windows Terminal, Alacritty, tmux с `set-clipboard on` и Termux с включённой настройкой OSC 52.
- **Локальная утилита** (`clipboard.command`): например, `["pbcopy"]`, `["wl-copy"]` или `["xclip", "-selection", "clipboard"]`. passh передаёт значение через stdin. Это полезно там, где терминал не поддерживает OSC 52, например в macOS Terminal.app.
- **Очистка:** через `clipboard.clear_after` passh тем же способом отправляет пустое значение. `copy` вне TUI перед завершением дожидается очистки.
- **Нет ни того, ни другого:** `copy` завершается ошибкой с подсказкой (`passh show <path> --field password | pbcopy`). Секрет при этом не выводится.
- `passh doctor` отправляет тестовую строку и затем очищает её, чтобы вы могли проверить свой терминал.
- История буфера обмена на клиенте (Universal Clipboard в macOS, Android, менеджеры буфера обмена) может сохранять копии. В README сказано, что терминал нужно исключить из этих инструментов.

### 6.4 По SSH

Специального серверного режима нет; passh — это просто команда на удалённой машине:

```bash
ssh -t pi passh                                       # TUI
ssh pi passh show work/github --field password | pbcopy
```

- TUI и запросам ввода нужен терминал, поэтому используйте `ssh -t`.
- Чтобы передать секрет с сервера через конвейер, сначала разблокируйте хранилище командой `ssh -t pi passh unlock`. После этого команды без `-t` работают, пока gpg-agent хранит парольную фразу в кеше.
- Для экспорта данных нельзя использовать `-t`: PTY превращает LF в CRLF и подмешивает stderr в поток (§7.1).

## 7. Экспорт и печать

### 7.1 Экспорт

```
passh export --format <csv|json|bitwarden-json|archive> [--tag t] [--folder f] [-o file]
             [--age <recipient> | --encrypt-to <gpg-id> | --confirm-plaintext] [--spreadsheet-safe]
```

| Формат | Содержимое | Шифрование | Назначение |
|---|---|---|---|
| `archive` (по умолчанию) | `tar.gz` папки хранилища, записи остаются зашифрованными GPG | Да | Резервная копия, переезд на другую машину |
| `json` | Собственная схема (§7.3) | С `--age` или `--encrypt-to` | Скрипты, миграция |
| `csv` | `folder,name,username,password,url,tags,notes`, кавычки по RFC 4180 | Как выше | KeePassXC и другие |
| `bitwarden-json` | Схема незашифрованного экспорта Bitwarden | Как выше | Vaultwarden/Bitwarden |

Правила:

- **Экспортируемые данные никогда не выводятся в терминал.** Используйте `-o file` или перенаправьте stdout.
- **Открытый текст** (любой формат, кроме `archive`, без `--age` или `--encrypt-to`) требует подтверждения:
  - если у passh есть терминал, пользователь вводит `EXPORT PLAINTEXT` в `/dev/tty`;
  - иначе требуется `--confirm-plaintext`.
- **`-o file`** создаёт файл с правами 0600. Если файл находится не на tmpfs, passh предупреждает, что открытый текст попадёт на постоянный диск.
- **Значения в CSV по умолчанию выводятся без изменений**, потому что файл предназначен для менеджера паролей. `--spreadsheet-safe` добавляет `'` в начало ячеек, которые начинаются с `= + - @`, табуляции или CR, чтобы предотвратить внедрение формул в электронных таблицах. Это меняет значения, включая пароли, поэтому не импортируйте такой файл в менеджер паролей.

### 7.2 Печать

```
passh print [--tag t] [--folder f] [--fields password,username,url] [--format pdf|txt] [-o file] [--confirm-plaintext]
passh print --web [--tag t] [--folder f] [--fields …]
```

- Действуют те же правила подтверждения, что и для экспорта открытого текста (§7.1).
- `pdf`: на чистом Go (`go-pdf/fpdf`) со встроенным моноширинным шрифтом UTF-8. Форматы A4/Letter, группировка по папкам, неоднозначные символы помечены (`0/O`, `1/l/I`), на каждой странице дата печати и «CONFIDENTIAL».
- `txt`: моноширинная вёрстка с разбивкой на страницы.
- `--web`: страница печати (§7.4).
- Распечатайте файл, затем удалите его; в README отмечено, что PDF, оставленные в папке «Загрузки», — это утечка.

{

  "exported_at": "2026-11-15T12:00:00Z",
  "entries": [
    {
      "path": "work/github",

### 7.4 Страница печати (веб)

Одноразовая HTTPS-страница с листом паролей. Вы открываете её в браузере на другом устройстве в LAN или VPN, печатаете, и при этом ничего нигде не сохраняется.

**Запуск**

- Требуется `print_web.enabled = true`.
- Запускается из TUI клавишей `P` или командой `passh print --web …`. Нужен терминал, и для подтверждения пользователь вводит `PRINT`.
- passh показывает:
  - URL для каждого адреса привязки и его QR-код для телефонов;
  - отпечаток сертификата и обратный отсчёт.

  `c` копирует URL в буфер обмена.
- Сервер работает внутри процесса passh; демона нет.

**Сеть**

- Слушает только на адресах интерфейсов из `print_web.interfaces` и только на **частных** адресах: RFC 1918, `100.64.0.0/10` (Tailscale) и IPv6 ULA `fc00::/7`.
  - Публичный адрес отклоняется.
  - Привязка к `0.0.0.0` или `::` никогда не выполняется.
- Соединения от клиентов вне `allow_from` закрываются до TLS. По умолчанию это подсети адресов привязки.
- Заголовок `Host` должен содержать адрес привязки или одно из имён `hostnames`, что защищает от DNS rebinding.
- passh не открывает порты в брандмауэре. Если брандмауэр блокирует порт, открыть его — ваша задача.

**Сертификат**

- **Никакого CA, ничего не устанавливается ни на одно устройство.** При первом использовании passh создаёт самоподписанный сертификат (ECDSA P-256, действителен 1 год) для адресов привязки и `hostnames`.
- Он хранит сертификат в `~/.local/state/passh/print-web/` (ключ с правами 0600) и использует его повторно, поэтому отпечаток не меняется.
- Если адреса изменились или срок действия сертификата истёк, passh создаёт новый и сообщает об этом.
- **Первый заход с устройства:** браузер предупреждает о сертификате. Сравните отпечаток SHA-256, который показывает браузер, с тем, который показывает passh, и только затем примите сертификат. Firefox может запомнить исключение навсегда; после этого любой другой сертификат на этом адресе снова вызовет предупреждение. Если принять сертификат без сравнения, вы останетесь уязвимы для активного атакующего в LAN (§9).
- Только TLS 1.3. Обычный HTTP никогда не предлагается.

**Токен и время жизни**

- URL имеет вид `https://<address>:<port>/p/<token>`, где токен — 128-битное случайное значение (`crypto/rand`, base64url).
- **Страница отдаётся один раз.** Первый `GET` с правильным токеном расходует его, и сервер останавливается после того, как ответ записан.
- Сервер также останавливается при первом из следующих событий:
  - истечение `print_web.ttl`, по умолчанию 5 мин, максимум 15;
  - блокировка (§5.2);
  - завершение passh;
  - `Esc` в диалоге печати;
  - 5 запросов к `/p/` с неверным токеном. Другие пути, например `/favicon.ico`, получают 404 и не учитываются.
- Предпросмотр ссылок и предварительная загрузка в браузере могут израсходовать токен раньше пользователя. Тогда пользователь видит «already used» и запускает страницу заново.

**Страница**

- То же содержимое и та же вёрстка, что у листа PDF (§7.2).
- Без JavaScript, внешних шрифтов и изображений. Пользователь печатает через Ctrl/Cmd+P.
- Записи расшифровываются в момент поступления запроса и передаются потоком. Каждое значение экранируется через `html/template` и дополнительно по S4.
- Заголовки ответа:
  ```
  Cache-Control: no-store
  Content-Security-Policy: default-src 'none'; style-src 'sha256-…'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
  Referrer-Policy: no-referrer
  X-Content-Type-Options: nosniff
  ```
  CSP блокирует скрипты и все исходящие запросы, поэтому даже при сбое экранирования страница не смогла бы никуда отправить пароли.
- После печати закройте вкладку. Браузеры могут сохранить страницу для восстановления сессии, а «Сохранить как PDF» или очереди печати могут оставлять файлы.

## 8. Резервное копирование и восстановление

Резервные копии хранилища и ключа GPG делаются отдельно, точно так же, как с `pass`.

| Что | Как |
|---|---|
| Хранилище | `passh sync` в удалённый репозиторий git или любое файловое резервное копирование папки хранилища (записи зашифрованы). `passh export --format archive` создаёт один файл |
| Секретный ключ GPG | Не хранится в хранилище. Сделайте его резервную копию сами, один раз: `gpg --export-secret-keys --armor <id> > key.asc` и храните её офлайн (она остаётся защищённой парольной фразой) или на бумаге с помощью `paperkey` |
| Конфигурационный файл | Не обязателен; в нём только путь к хранилищу и настройки |

Восстановление на новой машине:

1. установите `gpg` (и `git`) и скопируйте бинарный файл `passh`;
2. `gpg --import key.asc`;
3. клонируйте или скопируйте хранилище;
4. напишите конфигурационный файл с путём к хранилищу.

`pass` работает с тем же хранилищем и без passh.

### 10.3 Ключевые интерфейсы

```go
type Crypto interface {
    Decrypt(ctx context.Context, path paths.Safe) ([]byte, error)
    Encrypt(ctx context.Context, recipients []string, plaintext []byte) ([]byte, error)
    Forget(ctx context.Context) error // CLEAR_PASSPHRASE for the store's keygrips only
}

type Store interface {
    List(prefix paths.Safe) ([]paths.Safe, error)
    Read(path paths.Safe) (*entry.Entry, error)
    Write(path paths.Safe, e *entry.Entry) error // encrypt → write → index → commit (if git)
    Move(src, dst paths.Safe) error
    Remove(path paths.Safe) error
}
```

Значение `paths.Safe` может создать только валидатор.

## 11. Архитектурные решения

**ADR-1: Использовать системный `gpg`.** Ради совместимости с хранилищами и ключами pass, а также потому, что gpg-agent уже обеспечивает кеширование парольной фразы и pinentry. Цена: зависимость от GnuPG во время выполнения. Бэкенд на `age` через интерфейс `Crypto` остаётся возможным в будущем; он убрал бы эту зависимость, но нарушил бы совместимость с pass.

**ADR-2: Папки остаются основным способом организации; теги дополняют их**, с зашифрованным индексом (§4.3).

**ADR-3: Обычная CLI-утилита, которая не меняет систему.** Решение владельца в v0.5: один бинарный файл, один конфигурационный файл, запуск как обычной команды. Это заменяет модель ограниченного SSH-сервера из v0.2–v0.4. Компромисс: прав для отдельных устройств нет, и любой, кто может войти в систему под вашей учётной записью, получает полный доступ к passh.

**ADR-4: Минимальная защита, как в pass.** Решение владельца в v0.5: без подписанной истории, без закрепления получателей, без резервной копии ключа в составе хранилища, без заблокированной памяти. passh сохраняет только дешёвые правила из §5.3, не требующие настройки. Компромисс: подмена со стороны вредоносного удалённого репозитория не обнаруживается, как и в `pass`.

**ADR-5: Страница печати в LAN/VPN по HTTPS с самоподписанным сертификатом.** passh не должен менять хранилища доверенных сертификатов на устройствах, поэтому вместо локального CA он использует постоянный самоподписанный сертификат и проверку отпечатка (§7.4).

## 13. Критерии приёмки (v1)

### 13.1 Функциональные

1. Установка сводится к копированию бинарного файла и записи конфигурационного файла; `passh doctor` не сообщает об ошибках.
2. Существующее хранилище pass работает, если указать на него в `store`, и `pass` продолжает с ним работать.
3. TUI запрашивает парольную фразу один раз за сессию. После бездействия в течение `session.idle_ttl` следующая расшифровка запрашивает её снова.
4. Копирование работает через OSC 52, локально и по SSH, а также через `clipboard.command`; буфер обмена очищается через 30 с.
5. Экспорт Bitwarden JSON импортируется в Vaultwarden. Экспорт CSV импортируется в KeePassXC, и пароли, начинающиеся с `= + - @`, остаются без изменений.
6. Страница печати, запущенная на Pi, открывается в браузере ноутбука через LAN и через VPN. После принятия сертификата (отпечаток совпадает) страница печатается, а сервер останавливается после загрузки.
7. На новой машине для работы с passh достаточно `key.asc`, копии хранилища и конфигурационного файла.

### 13.2 Тесты безопасности

1. Отклоняются пути с `..`, абсолютные пути, пути с ведущим `-` или `.` в любом сегменте, с управляющими символами, а также символические ссылки, ведущие за пределы хранилища.
2. После любой команды, кроме явных `export -o` или `print -o`, на постоянном диске нет файлов с открытым текстом (тест по разнице состояний файловой системы).
3. Escape-последовательности (включая OSC 52) в содержимом записей отображаются обезвреженными в TUI и в `show`.
4. Сгенерированные пароли проходят тест равномерности хи-квадрат на 10⁶ выборках.
5. Экспорт открытого текста без подтверждения завершается ошибкой. Экспорт с подтверждением не содержит текста запроса. Запись экспортируемых данных в терминал отклоняется.
6. Блокировка заставляет gpg-agent забыть парольную фразу ключа хранилища, а другой кешированный ключ остаётся в кеше.
7. Страница печати:
   - привязывается только к частным адресам;
   - отдаётся один раз;
   - неверный заголовок `Host` или клиент вне `allow_from` отклоняются;
   - останавливается по TTL и при блокировке;
   - заголовки ответа соответствуют §7.4, а headless-браузер не делает исходящих запросов;
   - `<script>` или `<img>` в содержимом записи отображаются как текст.
8. Полная сессия (init, add, edit, export, страница печати, блокировка) ничего не пишет за пределами хранилища, конфигурационного файла, `~/.local/state/passh/` и своей временной папки (разница состояний файловой системы для `$HOME` и `/etc`, а также трассировка системных вызовов).
